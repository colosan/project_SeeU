# 세계관 소품 목록 (인터넷 속 가상 세계)

이 세계는 인터넷 안이다([DESIGN.md](DESIGN.md) "세계 컨셉"). 지하 고물상 = **휴지통 / 쓰레기 수집(GC) 구역**,
천장 슈트 = 위층에서 지운 데이터가 떨어지는 삭제 경로, 버려진 안드로이드 = 쓰지 않게 된 아바타·단종된 음성 모델의 몸체.
그래서 평범한 고물도 "데이터"라는 단서를 단다. 글자 설명보다 **사물 말장난**을 우선한다.

- 생성: `python tools/art/gen_digital.py` (없는 파일만 씀, 덮어쓰기는 `--force 파일명`, 아무것도 지우지 않음)
- 미리보기(3배): `python tools/art/gen_digital.py --preview=폴더` → 전/후 비교, 새 소품, 방 더미, 시유 크기 비교 시트
- 결과: `assets/env/basement/digital/` (96개). 도구: `tools/art/digitize.py`(디지털 단서), `tools/art/pixfont.py`(3x5 글꼴), `tools/art/gen_digital.py`
- 규칙은 [ART_PIPELINE.md](ART_PIPELINE.md)와 같다: 원본 해상도, 램프 색만, 실루엣 외곽선 한 번, 윗면+앞면만, 왼쪽 위 빛, 잡점 금지, 씨앗 고정.

## 1. 디지털 단서 (어떤 코드 그림에도 붙일 수 있음, `digitize.py`)

| 단서 | 모습 | 쓰는 곳 |
|---|---|---|
| 디레즈(de-rez) | 실루엣 한 모서리가 2x2/1x1 블록으로 깨지고, 몇 개가 위로 떠오르며 작아지다 희미한 청록 데이터가 됨(지워진 데이터가 썩어 가는 중) | 더미마다 1~3곳(꼭대기 아래 어깨에), 의자 등받이, 사다리 끝, 트러스 끝, 스피커 모서리 |
| 텍스처 빠짐 | 탁한 자홍(corrupt) + 가장 어두운 강철 체크무늬 | 아바타 가슴판, 의자 방석, 텍스처 빠진 블록. 이미지마다 예산 0~2개라 방 전체에 아주 조금 |
| 와이어프레임 | 물체 일부가 5px 격자 + 대각선의 어두운 청록 선만 남은 미완성 메시(속이 비쳐 보임) | 아바타 머리 반쪽, 몸통 오른쪽·팔 |
| 확장자/상태 글자 | 3x5 픽셀 글꼴, 3배에서 읽힘: .ZIP .WAV .TMP .EXE .BAK 404 ERR 01 MEM 56K UDP 418 EOL | 스티커·스텐실·화면 |

디레즈 조각은 원래 물체의 경계 상자 밖으로 나가지 않는다 → 디지털판은 원본과 **크기·밑선이 같다**.

**모든 바꿔치기와 단서 선택은 별도 난수(detail rng)로** 해서, gen_junk와 공유하는 난수 순서가 그대로다 → 더미의 구성(무엇이 어디에)이 원본과 똑같다.

## 3. 방 더미 1:1 교체본 (`dg_` + gen_junk 이름)

`dg_z_*`(10), `dg_c_*`(6), `dg_e_0..11`(12), `dg_t_*`(4), `dg_s_*`(7), `dg_a_spark/tv/rack/fan`(4), `dg_d_0..5`(6),
`dg_f_puddle1/2`, `dg_f_plate1`, `dg_f_coil1`, `dg_pile_a/b/c`, `dg_crate/amp/rack/tv` — 총 60개.

- 60개 모두 **원본과 픽셀 크기가 같고 구성·밑선이 같다**(검사함). 레이아웃 PLAN의 파일 이름만 바꾸면 된다.
- 애니메이션은 프레임 수·fps·프레임 크기가 원본과 같다: `dg_a_spark` 8f/10fps(불꽃 프레임 0·1·4·6 동일, 데이터 비트 한 점 추가), `dg_a_tv` 6f/6fps(밝기 패턴 동일, 화면은 오류 대화상자), `dg_a_rack` 6f/5fps(레거시 서버), `dg_a_fan` 4f/12fps(모서리 디레즈).
- `dg_s_worklamp`는 원본과 **완전히 같다**(빛의 원천이고, 지운 데이터가 아니라 GC 작업반의 도구).
- 바닥 장식(`dg_f_*`, `dg_d_*`, `dg_a_bugs`, `dg_a_lan`)은 gen_junk처럼 외곽선 고리가 없다.

## 8. 통합할 때 참고

- **런타임 램프**(`digitize.py`가 실행 중에 `pix.RAMPS`에 추가, pix.py는 안 고침). 받아들여지면 pix.py로 옮긴다:
  - `corrupt` `1e1320 381c35 54284c 723866 8e5080` — 탁한 자홍, 유일한 두 번째 강조색(글리치·텍스처 누락), 아주 조금만
  - `paper` `27241f 45413a 6a6559 928c7c b9b29f` — 문서·스티커·파일 아이콘·커서
  - `icon` `2a2416 4b4128 6f6040 94824f b5a265` — 폴더 아이콘(탁한 마닐라색)
  - 기존 램프와 겹치는 색 없음(검사함). gen_emission은 이 색을 모르므로 자홍은 빛나지 않는다(의도).
- **발광 마스크**: `tools/art/gen_emission.py`가 glow 2단 이상·spark를 자동으로 잡는다(화면, LED, 패킷, 비트, 홀로그램, 불꽃).
  추가 규칙이 필요한 곳: `basement/digital/dg_s_worklamp.png`(전구 BULB, 원본과 같은 규칙), `basement/digital/dg_a_rack.png`(빨간 LED `redp 4`).
  선택: `dg_a_meme_fine.png`의 불꽃 아랫부분(`warn 3`, `redp 3`)도 빛나게 하려면 규칙 추가.
- 새 소품의 배치 이유(레이아웃 PLAN) 예: 휴지통·GC 로봇은 슈트 더미 근처(이 방의 정체), 커서·로딩 링·홀로그램은 빛의 원천이 되는 작은 강조,
  127.0.0.1 매트는 출구(엘리베이터 홀) 쪽, 버그는 쓸린 길 가장자리 틈, CAPTCHA·트로이 목마·밈은 벽 쪽 분류 더미 옆.
