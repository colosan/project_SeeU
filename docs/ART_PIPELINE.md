# 그림 만드는 법 (배경·소품)

**핵심: 규칙을 먼저 고정하고, 그림은 코드로 그리거나 PixelLab으로 형태만 뽑아 코드로 마감한다. 색과 마감은 항상 우리 코드가.**

## 1. 왜 이렇게 하나 (실패에서 배운 것)
- PixelLab 소품은 각진 물체를 **대각선(등각) 시점**으로 그린다. `create_map_object`(맵 소품 전용)도, 시점을 "low/high top-down"으로 줘도 상자는 대각선. → 각진 물체는 코드로.
- 큰 랜드마크를 AI로 한 장씩 뽑으면 물체마다 크기·선·시점·거리감이 달라 한 화면에 섞이지 않는다.
- AI는 "많이 쌓인 것"을 작은 같은 물체의 반복으로 그려서 환공포증 같은 그림이 나온다.
- `create_image_pixflux` + 밑그림(img2img)은 각도는 지키지만 품질이 낮다.
- 이미 만든 그림을 확대하면 픽셀 규격이 깨진다 — 금지.
- 쓸 만했던 PixelLab: 나무·로봇·케이블처럼 둥근 것(`create_map_object`), 캐릭터(`create_character` v3), 걷기(`animate_character` skeleton-v3).

## 2. 코드로 그리기 — `tools/art/pix.py`
- `Pix(w, h)`: 픽셀마다 (재질, 단계)를 저장. `rect/hline/vline/ellipse/paste`, `outline()`(실루엣에 sel-out 한 겹), `bbox_crop()`, `image()`.
- `box(p, x, y, w, d, h, mat, front, top)`: 정면 3/4 상자. 윗면(깊이 d) 밝게, 앞면, 윗모서리 하이라이트, 오른쪽 열 한 단 어둡게. 부품에는 외곽선을 두르지 않는다.
- `RAMPS`: 재질별 2~5단(0 = 가장 어두움 = 그 재질의 외곽선). steel, plastic, card, shell, rubber, glow(유일한 강조색), warn, redp, tarp, oil, spark.
- 새 재질이 필요하면 RAMPS에 추가(탁하고 채도 낮게).

## 3. 고물 생성기 — `tools/art/gen_junk.py`
- 부품 함수(상자·앰프·서버 랙·TV·봉투·스피커·마이크 스탠드·신시사이저·모니터·조명·트러스·로봇 머리/몸통·팔레트·드럼통·타이어·배관·환풍기·의자·사다리·철판·탱크): `fn(p, x, y, rng)` → (윗면 bbox, 폭).
- `mound(seed, kinds, n, w, h, peak)`: 산 모양 더미. 비대칭 꼭대기, 울퉁불퉁한 밑자락, 몸통(잡동사니 덩어리) 위에 부품을 먼 것부터 그림, 앞으로 미끄러진 물건. 외곽선 한 번.
- `stack(seed, parts)`: 위로 쌓은 묶음(드럼통 위 TV 등). 바닥 장식(`puddle`, `floor_plate`, `coil`)은 충돌 없는 장식.
- 애니메이션: `spark_cable`, `flicker_tv`, `blink_rack`, `spin_fan` → 프레임을 가로로 붙인 PNG(`a_*.png`). Godot에서 `pixel_prop`의 `frames`/`fps`로 재생.
- 파일 이름 규칙: `c_*` 구성용 큰 덩어리, `e_*` 벽 따라 놓는 더미, `z_*` 테마 더미, `t_*` 쌓은 묶음, `s_*` 단품, `f_*` 바닥 장식, `a_*` 애니메이션.
- 같은 명령은 늘 같은 그림(씨앗 고정). 없는 파일만 쓰고, 덮어쓰기는 `--force 이름`. 아무것도 지우지 않는다.

## 4. PixelLab 형태 가져오기 — `tools/art/import_pixellab.py`
- `SOURCES`에 (출력 이름: PixelLab 맵 오브젝트 id, 무채색 기본 재질)을 적는다. 원본은 `build/pixellab_cache`에 캐시.
- 처리: 색상 계열 → 재질 램프, 밝기가 가까운 단계로 재매핑 → 재질 안 외딴 점 평탄화, 떠도는 점 제거 → sel-out 외곽선.

## 5. Godot 쪽
- `scripts/world/pixel_room.gd`: 방 배경(원본 해상도) 3배 표시 + 벽 충돌(Rect2, 원본 px) + 카메라 범위.
- `scripts/world/pixel_prop.gd`(`@tool`): 소품. 기준점 = 밑변 가운데. 실루엣 밑선을 따라가는 접지 그림자, Y 정렬, 충돌(아래 35%), `solid=false`면 바닥 장식, `frames/fps` 애니메이션. 비스듬한 소품은 `flip_h` 금지(옆면 방향이 바뀜).
- 조명: CanvasModulate로 전체를 어둡게 + PointLight2D(계단식 GradientTexture2D, interpolation_mode=1). 빛마다 보이는 원천.

## 6. 방 배치 — `tools/layout_*.py`
- 방마다 PLAN 목록에 (폴더, 파일, x, y, **이유**, 옵션)을 적고 스크립트가 `.tscn`을 만든다(씬에도 이유가 주석으로 남음). 씬을 손으로 고치지 말고 PLAN을 고친다.
- 검사: 단단한 물건이 길(통로)이나 시작 양탄자 위에 있거나, 길 **앞쪽에 서서 그림이 길을 가리면** 실패.
- 지하 방의 이야기: 슈트 아래 가장 큰 산 → 굴러떨어진 작은 것들 → 양탄자(시작) → 출구까지 불도저로 민 통로(양옆에 밀린 고물) → 벽 쪽은 종류별 분류 더미 → 끊어진 전선 스파크·깜빡이는 TV·환풍기 → 작업등.
- 길 표시는 환경으로만: 쓸린 밝은 바닥, 가장자리 부스러기 둔덕, 바퀴 자국, 작업등. 화살표·테이프 같은 표시는 쓰지 않는다.

## 7. 다른 에이전트가 준 가이드에서 받아들인 원칙
- 기준 화면을 먼저 완성하고 규칙(크기표·팔레트·외곽선)을 뽑는다. 시안은 가볍게, 실제 게임 화면에서 같은 배율로.
- 디테일은 놓는 것, 뿌리는 것이 아니다. 쉴 곳을 둔다. 명암 위계 먼저. 극적인 느낌은 빛과 구도에서.
- 깨끗하게 한답시고 바닥을 한 색으로 밀지 않는다(타일 이음매·결은 살린다).
